# Second Brain OS V96 · STABLE CORE

V96 — первая итерация большой технической стабилизации. Она не пытается за один релиз переписать весь Second Brain OS. В этой версии исправлены наиболее опасные проблемы ядра: невалидный cloud runtime, противоречивый Firebase, небезопасная очистка PWA-кэшей, разбросанные номера сборки и отсутствие отдельного проверяемого backup перед новой итерацией.

## Что изменено

### 1. Cloud runtime восстановлен

`cloud-sync.js` снова является валидным JavaScript. До настройки Firebase приложение честно показывает «Синхронизация не настроена» и не выводит поля email/пароля. Firebase SDK больше не загружается без необходимости.

После частной настройки доступны:

- регистрация и вход по email;
- ручная отправка локального состояния;
- ручная загрузка облачной копии с подтверждением;
- backup перед применением облачной копии;
- выход из аккаунта;
- понятные статусы ошибок.

Автоматическое опасное объединение финансовых данных не выполняется.

### 2. Firebase приведён в корректное состояние

- `firestore.rules` теперь содержит настоящие Firestore Rules;
- доступ разрешён только владельцу `request.auth.uid == userId`;
- `firebase.json` стал валидным;
- старые файлы с реальным Firebase API key обезврежены;
- основной `firebase-config.js` по-прежнему содержит только безопасный шаблон.

### 3. Единая версия приложения

Добавлен `src/app/version.js` — единый источник:

- версии приложения;
- build id;
- версии схемы данных;
- версии кэша;
- публичной подписи сборки.

Активные runtime-слои и интерфейс показывают `V96 · STABLE CORE`.

### 4. Безопасный PWA

- `index.html` добавлен в precache;
- Service Worker удаляет только кэши с префиксом `second-brain-os-`;
- больше не удаляются посторонние кэши origin;
- новая версия не активируется посреди редактирования без подтверждения;
- активные V96-ресурсы входят в shell;
- manifest обновлён до V96.

### 5. Backup перед V96

`src/storage/backup.js` создаёт один снимок перед первой работой V96:

- исходный JSON `secondBrainOS.v1`;
- метаданные сборки;
- количество коллекций;
- полный снимок в IndexedDB;
- дополнительную raw-копию в localStorage только если размер безопасен.

Если данные ещё не успели загрузиться, backup повторяется через 1,8 и 5 секунд. Пустой снимок не помечается успешным.

### 6. Диагностика

В настройках появляется блок «Стабильность и сохранность»:

- текущая версия;
- наличие основного ключа данных;
- дата backup V96;
- честный статус облака;
- количество ошибок запуска;
- кнопка копирования технического отчёта без содержимого личных записей.

### 7. Accessibility foundation

- видимый `focus-visible`;
- более читаемые подписи и поля настроек;
- cloud-поля имеют label и aria-label;
- поддержан `prefers-reduced-motion`;
- красный AI-бейдж закреплён внутри кнопки.

## Сохранность данных

Основной ключ не изменён:

`secondBrainOS.v1`

V96 не содержит команд очистки localStorage или IndexedDB. Кнопка очистки интерфейса удаляет только PWA-кэши Second Brain OS.

## Что намеренно не выполнено в этой итерации

Чтобы не повторить ошибку «большого взрыва», в V96 ещё не выполнены:

- полное разделение 800+ КБ `index.html`;
- удаление всех сотен legacy-файлов;
- единая формальная схема всех сущностей;
- полноценный модуль трейдинга;
- двухстороннее автоматическое разрешение конфликтов устройств;
- полный комплект E2E-тестов на реальном GitHub Pages origin.

Это задачи следующих итераций после проверки V96 на реальных данных.
