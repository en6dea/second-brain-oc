# Second Brain OS — контекст проекта

Документ описывает приложение таким, какое оно сейчас. Прежняя версия
контекста называла файлы `app-v104-full.js`, `app-v112-finance-center.js` и
другие — их больше нет, код сведён в один `app.js`. Ниже актуальная картина.

## Что это

Персональный Life OS: день, привычки, цели, задачи, календарь, финансы,
покупки, долги, личные записи, знания, планирование, обзоры.

Главный принцип прежний: **новая функция встраивается в систему, а не
становится отдельной страницей.** Данные вводятся один раз и переиспользуются:
покупка → план → календарь → операция → аналитика → обзор.

## Архитектура

Frontend без сборки и фреймворков — HTML, CSS, JavaScript. Переписывать на
React/Vue не нужно.

### Про единый app.js

Раньше файлов было около тридцати: `app-v91`, `app-v93`, `app-v103`,
`app-v104`, `app-v108`, `app-v112` — и все подключались одновременно.
Прежний контекст справедливо предупреждал: нельзя считать, что старший номер
заменяет предыдущие. Теперь это не нужно — слои склеены в порядке исполнения
в один файл, границы отмечены комментариями вида:

```js
/* ===== source: app-v104-full.js ===== */
```

Искать нужное место следует по этим меткам.

## Хранение данных — критически важно

| | |
|---|---|
| Полное состояние | IndexedDB → `SecondBrainOSDurableStorage` → `records` → `main-state` |
| Компактное зеркало | `localStorage['secondBrainOS.v1']` — только служебные поля |
| Копии | те же `records`, ключи `backup:*`, `daily:*` |

`localStorage` **не** является хранилищем полного состояния.

**Никогда:** `localStorage.clear()`, очистка IndexedDB, новый пустой state
поверх существующего, удаление неизвестных полей, сброс данных при обновлении
версии, переименование ключей без миграции.

Принцип изменения: прочитать состояние → изменить только нужные поля →
сохранить целиком. Неизвестные поля сохраняются дословно.

Подробная модель — в [DATA-MODEL.md](DATA-MODEL.md).

## Темы

Светлая — оформление проекта, включена по умолчанию. Тёмная доступна
переключателем в шапке (кнопка внешнего вида) и запоминается в
`localStorage['secondBrainOS.visualThemeMode']`: `light`, `dark`, `system`.

Темы **взаимоисключающие**, а не наслаиваются: `styles-dark-base.css` — это
тот же `styles.css` с другими цветами, и при одновременном подключении часть
правил со `!important` оставляет тёмный текст на тёмном фоне. Контроллер в
`app.js` включает одну таблицу и отключает другую; тёмная подгружается только
при выборе.

Тёмные значения прежних палитр (`--v78-*`, `--v87-*`, `--v88-*` и остальные)
генерируются `make-dark-tokens.py` из светлых и дописываются в конец
`styles-lumen.css`. Правки вносите в скрипт и пересобирайте, иначе они
потеряются при следующей генерации.

## Интерфейс

Светлый, premium / quiet luxury: мягкие фиолетовые оттенки, аккуратные
акценты, большие скругления, лёгкие тени, воздух, шрифт Onest, цветные
иконки, минимум визуального шума.

Не делать случайный редизайн отдельных страниц. Новая страница должна
выглядеть так, будто всегда была частью системы.

Следить за: иконками, выравниванием, переносами, скруглениями, состояниями
кнопок, кликабельностью всей ожидаемой области, мобильной версией,
отсутствием белых углов внутри скруглённых контейнеров и наложений текста.

Если пользователь видит число или рекомендацию — должно быть понятно, откуда
она взялась.

## Финансы

Разделы: `finance`, `finance-accounts`, `finance-planning`,
`finance-operations`, `debts`, `finance-calendar`, `finance-weekly`.

**Собственные деньги считаются отдельно от кредитных.** Собственные типы
счетов: `cash`, `bank_card`, `deposit`, `savings`, `other`. Кредитный лимит не
увеличивает количество собственных денег.

Свободный остаток = собственные деньги − резервы − обязательства − минимальный
резерв.

**План ≠ расход.** План — намерение. Операция создаётся только после действия
«Провести»: создаётся `operation`, уменьшается `actualBalance` счёта, план
получает статус оплаты, связанный резерв закрывается, показатели
пересчитываются. Одна сумма не должна учитываться дважды.

**Отложенные покупки.** Желание фиксируется, не считаясь расходом; позже
переносится в план (`deferredPurchase → financePlan`) и становится расходом
только после оплаты.

**Незаполненное ≠ ноль.** Остаток счёта `null` означает «неизвестен» и не
участвует в суммах. Молчаливый ноль создаёт ложную уверенность в том, сколько
денег есть.

**Платёж по долгу делится** на тело, проценты и штрафы; основной долг
уменьшает только часть «тело». Поэтому срок погашения считается амортизацией,
а не делением остатка на платёж.

## Как работать над задачами

1. Найти существующую реализацию — по меткам `/* ===== source: ... ===== */`.
2. Понять зависимости.
3. Использовать и расширить существующие компоненты.
4. Сохранить обратную совместимость.
5. Проверить сохранение данных.
6. Проверить смежные разделы.

После изменения проверить: загрузку, отсутствие ошибок в консоли, переходы
между разделами, кликабельность, ввод и сохранение, повторное открытие,
сохранность данных, обе темы, desktop и mobile.

Задача не выполнена, пока код лишь выглядит правильным.

## Версионирование и кэш

После существенных изменений поднять версию, Build ID и cache version
в `version.js`, а также `?v=` в `index.html` и `sw.js`. Удобнее одной командой:

```bash
sed -i 's/v115-r6/v115-r7/g' index.html version.js sw.js
```

Если пользователь видит старую версию — сначала проверять кэш и подключение
файлов, а не переписывать функциональность. Локально запускать
`python dev-server.py`: обычный `python -m http.server` кэширует и прячет
именно этот класс ошибок.
