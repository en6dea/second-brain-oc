## Главное архитектурное решение

`v2` читает и пишет **то же хранилище**, что старое приложение:
IndexedDB → `SecondBrainOSDurableStorage` → `records` → `main-state`.

Отсюда следует всё остальное:
- миграции нет и не требуется;
- раздел, не перенесённый в `v2`, открывается в старом приложении с теми же данными;
- откат — это закрыть вкладку.

Проверено: отметка привычки, поставленная в `v2`, видна старому приложению.

## Формы — сделано

`v2/src/modal.js` — общий механизм окон и полей, `v2/src/actions.js` — сами
формы: обязательство, платёж по долгу, стратегия погашения, счёт, сверка
остатков, операция, привычка, задача.

Инвариант соблюдён и проверен: пустое числовое поле сохраняется как `null`,
а не как 0 (`numberOrNull` в `store.js`). Очистка поля в сверке остатков
возвращает счёт в состояние «не подтверждено», а не обнуляет его.

Форма платежа не даёт разойтись частям: если тело + проценты + штрафы не
равны общей сумме, окно остаётся открытым с объяснением.

**Про кэш при доработке:** модули подключаются по адресу без версии, поэтому
после правки файла в `v2/src/` нужно поднять `?v=` у `app.js` и `styles.css`
в `v2/index.html` — иначе браузер возьмёт старый код из кэша. На этом я уже
один раз попался.

## Как проверять

Локальный сервер (порт 8834 разрешён политикой браузера в этой среде):

```bash
python -m http.server 8834
```

Старое приложение: `http://localhost:8834/index.html`
Новое: `http://localhost:8834/v2/index.html`

Тестовые данные (пишут в общее хранилище, копия создаётся автоматически):

```js
const m = await import('/v2/src/seed.js'); await m.seed();
```

Полезная проверка после правок: пройти маршруты и убедиться, что нет светлых
поверхностей и нечитаемого текста — в старом приложении такой аудит выявил
невидимые кнопки, которые глазом не замечались.
